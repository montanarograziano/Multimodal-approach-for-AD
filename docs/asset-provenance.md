# Asset provenance ledger

This page is a factual audit of binary/data assets committed to the
repository root, based on file format inspection and `git log --follow`
history. It does **not** modify, remove, or reinterpret these assets:
per the migration plan, historical artifacts are left untouched until a
dedicated follow-up (with authors' input) decides their fate.

!!! danger "Unresolved provenance: read before redistributing this repository further"
    Two of the files below (`mri1.nii`, and to a lesser extent
    `resized_pos_mri.npy` / `resized_neg_mri.npy`) have the technical
    signature of **real, single-subject neuroimaging data**, in a project
    whose only data source is OASIS-3, a dataset distributed under a Data
    Use Agreement that restricts redistribution. Whether this specific
    volume is real OASIS-3 subject data, a defaced/anonymized sample, or a
    phantom/synthetic scan **cannot be determined from the file alone**.
    This is flagged as an open compliance question for the maintainers,
    not resolved here, and not treated as "probably fine."

## Method

For each asset: inspected file format/header (NIfTI header fields for
`.nii`, NumPy header for `.npy`, image metadata for `.png`), cross-referenced
against the shapes/filenames the legacy notebooks are documented to
produce (see [legacy notebook inventory](legacy-notebooks-inventory.md)),
and looked up first-introduction commit via `git log --follow`.

## What this PR does and does not do

- **Does**: document the above findings explicitly, so the ambiguity is
  visible instead of silently assumed away.
- **Does not**: delete, re-encode, hash-verify against an external OASIS-3
  manifest, or otherwise alter any of these files. That requires input
  from the paper authors (who know the actual source of `mri1.nii` and the
  `resized_*_mri.npy` pair) and, if real subject data is confirmed, a
  decision on history rewriting (`git filter-repo` or equivalent) that is
  out of scope for a documentation PR.

## Package distribution

`uv build`'s sdist (`tool.hatch.build.targets.sdist.only-include` in
`pyproject.toml`) uses a strict allowlist: only `src/multimodal_ad`,
`pyproject.toml`, `README.md`, `LICENSE`, and `CITATION.cff`. None of the
flagged files above (or `samples/`, `notebooks/`, `docs/`, `tests/`) are
included in the sdist or wheel; see `tests/test_distribution.py` for the
regression test that builds both artifacts and asserts this. This mitigates
**redistribution via PyPI/package artifacts only**; it does not remove these
files from the working tree or from git history (see follow-up below).

## Recommended follow-up (not performed here)

1. Ask the paper authors directly whether `mri1.nii`,
   `resized_pos_mri.npy`, and `resized_neg_mri.npy` contain real OASIS-3
   subject data or synthetic/phantom data.
2. If real subject data is confirmed and redistribution is not covered by
   the OASIS-3 DUA, remove these files from git history (not just the
   working tree) before any further public distribution of this
   repository, and replace their notebook/demo usages with the synthetic
   fixtures described in [Data access & contracts](data-access.md).
3. If synthetic/phantom or otherwise clear, replace this ledger's
   "Unresolved" status with the confirmed origin and a citation/reference.
